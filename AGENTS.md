# Project instructions

Read `docs/research-plan.md` and `docs/source-register.md` before research changes.

- Keep paper reproduction, source compatibility and extension experiments
  separately identified in configurations, outputs and conclusions.
- Use synthetic data. Keep credentials, participant records, private application
  details and machine-specific paths out of repository files and published outputs.
- Preserve source revisions, seeds, environment versions and input/output hashes.
  Investigate discrepancies instead of silently changing a reproduction target.
- Keep response generation, estimation, item selection and analysis independent.
  Changes to research methods must include updated specifications and checks.
- Keep original upstream code and its notices distinct from the independent
  implementation. Check the recorded license before distributing derived code.
- Predeclare confirmatory comparisons and tolerances. Label exploratory analyses
  and report inconclusive or failed reproduction attempts.
- Record findings as conditional on the simulated model. Stable ratings and
  immediate accuracy do not establish retention or assessment validity.
- Keep documentation accurate about implementation status. A proposed command,
  test or experiment must not be presented as implemented or completed.
